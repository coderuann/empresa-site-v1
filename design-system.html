Design System
Foundations.

Especificação técnica para consumo direto por Design (Figma Variables) e Engenharia (CSS custom properties / Tailwind / Style Dictionary). Arquitetura em 3 tiers: Primitive → Semantic → Component.

Escala tipográfica1.250 · Major Third
EspaçamentoBase 8pt
ModoLight + Dark
Versão1.0 · 2026
Este documento é executável. Todo componente abaixo é HTML real consumindo os mesmos tokens da especificação — nenhum valor hard-coded. Alterne o dark mode na barra lateral: nada nos componentes muda, só a camada semântica é reatribuída. É essa a prova de que a arquitetura de tokens funciona.

08 / Foundation

Motion

Movimento é feedback, não decoração. Curva única para todo o sistema — variação acontece na duração, não no easing.

TokenValorUso
duration-fast120msHover, focus, mudança de cor
duration-base200msDropdown, tooltip, toggle
duration-slow320msModal, drawer, transição de página
easing-standardcubic-bezier(.2,0,0,1)Padrão único do sistema
Acessibilidade: respeitar prefers-reduced-motion — reduzir todas as durações a 0.01ms quando ativo, mantendo o estado final.

16 / Engenharia

Token Export

Fonte única de verdade em formato W3C DTCG. Pipeline recomendado: Tokens Studio (Figma) → tokens.json → Style Dictionary → CSS / Tailwind / Swift / XML. Isso elimina divergência entre Figma e código desde o dia 1.

tokens.json — formato W3C DTCG

{
  "color": {
    // TIER 1 — primitive
    "blue": {
      "600": { "$value": "#1E3A8A", "$type": "color" },
      "400": { "$value": "#5C7CFA", "$type": "color" }
    },
    "sand": {
      "0":   { "$value": "#F7F5F1", "$type": "color" },
      "900": { "$value": "#1A1815", "$type": "color" }
    }
  },
  // TIER 2 — semantic (referencia tier 1)
  "bg": {
    "base":    { "$value": "{color.sand.0}",   "$type": "color" },
    "surface": { "$value": "#FFFFFF",          "$type": "color" }
  },
  "action": {
    "primary": { "$value": "{color.blue.600}", "$type": "color" }
  },
  "spacing": {
    "md": { "$value": "16px", "$type": "dimension" },
    "lg": { "$value": "24px", "$type": "dimension" }
  },
  // TIER 3 — component (referencia tier 2)
  "button": {
    "primary": {
      "bg":      { "$value": "{action.primary}", "$type": "color" },
      "padding": { "$value": "{spacing.sm} {spacing.md}", "$type": "dimension" }
    }
  }
}

Convenção de nomenclatura

TierPadrãoExemplo
1 · Primitivecolor-{matiz}-{step}color-blue-600
2 · Semantic{categoria}-{intenção}-{variante}action-primary-hover
3 · Component{componente}-{variante}-{propriedade}button-primary-bg
Regra inviolável: componente nunca referencia tier 1 diretamente. Se um componente aponta para color-blue-600 em vez de action-primary, o dark mode e qualquer rebrand futuro quebram. Isso é o item nº1 do checklist de code review.
17 / Engenharia

Governança

O sistema só existe se for adotado. Com dois fundadores, o processo pode ser leve — mas precisa ser explícito antes do primeiro contratado entrar.

ÁreaDefinição
VersionamentoSemVer. MAJOR = breaking (token removido/renomeado) · MINOR = adição · PATCH = correção visual
ContribuiçãoRFC curto em issue antes de adicionar componente. Toda adição precisa justificar por que não é variante de um componente existente.
OwnershipDefinir 1 owner do sistema. Decisão de token exige acordo dos dois sócios; decisão de componente é do owner.
ChangelogToda release documenta o que mudou e o caminho de migração de breaking changes.
DeprecationToken ou componente marcado como @deprecated por 1 ciclo antes da remoção. Nunca remover direto.

Definition of Done — novo componente

#Critério
01Consome exclusivamente tokens semânticos — zero valor hard-coded
02Todos os estados cobertos: default, hover, focus, active, disabled, loading, error
03Auto Layout no Figma + Component Properties espelhando as props de código
04Contraste AA verificado em light e dark mode
05Navegável por teclado, foco visível, semântica ARIA correta
06Documentado: anatomia, props, do/don't, quando NÃO usar
07Responsivo validado nos 3 breakpoints

Anti-padrões — o que quebra o sistema

✕  Componente referenciando token primitivo em vez de semântico
✕  Valor de espaçamento fora da escala 8pt porque "ficou melhor"
✕  Novo componente que é, na prática, variante de um existente
✕  Cor comunicando estado sem texto de apoio
✕  Terceira família tipográfica introduzida "só nesse caso"
✕  Documentar depois de escalar — a dívida vira irreversível
